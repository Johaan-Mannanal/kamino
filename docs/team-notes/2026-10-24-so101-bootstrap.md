# SO101 model and name mapping bootstrap

Branch: `codex/backend-pipeline`. Hardware integration remains pending Windows
calibration/config and pose evidence.

## Added

- Unmodified Apache-2.0 MuJoCo Menagerie SO101 model, 18 STL assets, upstream
  README/LICENSE and a per-file SHA-256 manifest. Pin:
  `f3b6013629c7b94f8ee93fd977b161fa8350f9bc`.
- `python -m photo2sim.simulation.so101`: standalone simulation-only inspection,
  name-based joint/actuator resolution, range/address report, and two-second
  finite-state hold check. Reports explicitly mark hardware mapping unverified.
- [Model/mapping documentation](../../examples/so101/README.md) and
  [Windows inventory request](../handoffs/yash-so101-mapping.md).

## Verified on Johaan's Mac

Python 3.13.7, MuJoCo 3.3.7, NumPy 2.5.4.

- Six hinge joints and six corresponding position actuators resolve by name.
- Two simulated seconds / 400 steps at the upstream 5 ms timestep.
- Finite state; zero MuJoCo and Python warnings in that smoke check.
- Maximum displacement from initial zero-target pose: 0.000848 rad.
- All 22 downloaded source file hashes match the saved manifest.
- Eight new tests cover mapping despite reversed actuator order, missing/wrong
  actuator targets, invalid duration, and loading/stepping the pinned model.
  They failed before implementation and then passed.
- Full suite: **194 passed, 1 skipped**, with one existing Starlette/httpx
  deprecation warning. Skip is the unavailable optional uagents_core dependency.
- Ruff lint/format and dependency consistency pass.
