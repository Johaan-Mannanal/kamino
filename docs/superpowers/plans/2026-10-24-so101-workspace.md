# SO101 combined workspace implementation plan

> **For agentic workers:** Use superpowers:executing-plans for inline implementation.

**Goal:** Build a portable robot + accepted object + tabletop scene and prove a
repeatable offline reset/hold/drop, while real-arm mapping remains pending.

**Architecture:** Reuse the pinned robot and existing metre-based object exporter.
Compose a derived XML scene with explicit contact settings; preserve originals,
licenses, property provenance and saved orientation. Keep this outside the web API
and outside hardware control until Windows calibration evidence arrives.

**Tech Stack:** Existing Python, Pydantic, MuJoCo, NumPy, trimesh; no new dependencies.

**Spec:** This turn's scoped continuation plus `examples/so101/README.md` acceptance
steps. Implementation choice: tabletop Z=0, robot mount at origin, default object
XY=(0.30,0.10) m, all robot targets zero radians. These are simulation assumptions,
not user measurements or hardware commands.

## Global constraints

- No LeRobot imports, serial connections, physical motion, or paid API calls.
- Original robot source and accepted object bundle remain unchanged.
- Use 0.0001 s combined timestep; preserve original servo gains and force limits.
- Reuse box-proxy contact assumptions and fixed 1 mm penetration limit.
- Label reset pose, tabletop, object placement and servo dynamics as uncalibrated.
- Existing output directories must not be overwritten; all scene paths portable.

## Review focus

- Object free-joint ordering must not shift robot actuator/qpos mapping.
- Reused robot defaults must not silently alter object friction/contact/inertia.
- Invalid limits, incomplete poses, nonfinite data, or off-table placement rejected.
- Reset must restore qpos, qvel, time and controls, including after arbitrary mutation.
- Passing a drop/hold must not be labeled successful manipulation or real fidelity.
